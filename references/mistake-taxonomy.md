# 错解分类法与数据强度纪律

> 本文件的分类框架改写自 [ICPC-Problem-Creator.skill](https://github.com/Lumine2024/ICPC-Problem-Creator.skill)（MIT License, Copyright (c) 2026 Lumine2024），并适配 ProbHub 的期望矩阵与数据分组语义。

目的：把"可能出现的错误程序"系统化，而不是靠临场灵感想两三个错解。每个保留下来的错解都必须落入 ProbHub 的结构化宿命：`solutions.wrong[].expected` 声明 `status`/`groups`/`forbid`，`data.groups` 用 `targets` 指认击杀数据。"至少挂一个点"不是本项目的判定语义。

## 1. 使用方式

拿到题目后，先做一张简短清单，再开始编码：

1. 正解思路是什么；
2. 哪些思路看起来像正解、但实际上是错的；
3. 哪些程序逻辑上可能正确、但复杂度或实现会错；
4. 每一类错法需要什么数据才能**稳定**被卡掉（不是碰运气）。

枚举必须至少覆盖三层：**思路层、复杂度层、实现层**。每层至少落出一个可编译、真的会错的程序；某层确实不适用时，在交付说明中写明原因。与正解等价的"错解"不得保留。不要只枚举 WA 型错法：要主动枚举"复杂度接近但会 TLE""实现细节错但小样例能过"的错法。

## 2. 思路层错误

- 暴力或伪暴力：全枚举；带一点剪枝但本质仍爆炸；"先随机几次试试""启发式调一调"。
- 错误贪心：只看局部最优；排序 key 不完整；把必要条件当充分条件；以为交换论证成立，实际不成立。
- 错误二分：答案根本不单调；判定函数不单调；上下界用错；`mid` 或循环边界差一位。
- 错误 DP：状态缺信息；状态多一维导致复杂度炸；转移漏项；转移顺序错误；滚动数组覆盖顺序错误；把剪枝错当正确性证明。
- 错误图论建模：实际是最短路却写成普通 BFS/暴力松弛；应离线处理却在线硬算；实际是 DAG/树结构却套过重模型；不是网络流硬往流上套。
- 错误数学建模：公式只在某个前提下成立却被默认推广；逆元存在条件不满足仍硬用；忽略 `n >= mod`；把浮点比较当精确判定。

## 3. 复杂度层错误

这些错法常常逻辑"几乎对"，但应当在系统测试中超时：

- 与正解同思路但多一个 `log`；
- 每次询问/每个起点/每个状态重复整套预处理；
- 应为线性或 `O(n log n)` 却写成 `O(n sqrt n)`、`O(n log^2 n)`、`O(n^2)`；
- 理论复杂度正确但常数极大，在极限数据上会死。

典型例子：该用 Dijkstra 却用逐边松弛类算法；每个询问做独立 DFS/BFS；LCA 结构多套一层 log；`O(n^2)` 回文/子串方案冒充 `O(n log n)`。

配置提示：期望 TLE 的错解写 `expected: {status: TLE, groups: [<近上界组>], forbid: [WA, RE, FAIL]}`——若它同时还会 WA，说明它其实属于思路层，重新归类。

## 4. 实现层错误

这些错法可能在样例和小随机数据上全过，必须用定向构造击杀：

- 下标/边界：0/1 下标混淆；区间开闭错误；`l < r` 与 `l <= r` 写错。
- 数值：`int` 溢出；`INF` 太小；`mid = (l + r) / 2` 溢出；乘法未转 `long long`。
- 多测与初始化：忘记清空数组、visited、lazy tag、并查集；全局状态跨测试组串味。
- 顺序：遍历顺序写反；先更新后使用或反之；滚动数组覆盖原值。
- 标准算法误实现（按正解依赖的算法族逐项检查）：
  - Dijkstra：优先队列比较方向反；pair 顺序写成 `(node, dist)`；缺 stale-state 判断重复扩展；`INF` 太小。
  - Tarjan/SCC/桥/割点：lowlink 更新条件错；on-stack 判断错；parent edge 处理错。
  - LCA/树剖：深度对齐错；区间映射边界错；多一层 log 被大数据卡掉。
  - 线段树/Fenwick：懒标记下推时机错；下标偏移；区间合并信息不完整。
  - 组合数取模：逆元不存在仍硬除；`n >= mod` 不做 Lucas/prime power/CRT 处理。
  - 字符串：哈希无二次确认；KMP/Z/SA/SAM 边界错；忽略全相同串、交替串、极短串、超长重复串。

## 5. 计算几何精度错法族

题目涉及几何时，把精度问题当成一整类独立错法系统枚举，而不是附带一提：

- 角度比较、近似平行、近似共线的判定抖动；
- 叉积/点积符号在临界值附近翻转；
- 相切、擦边、共点等边界情形；
- `eps` 过大（放走错误）与过小（误杀正确）；
- 浮点与整型混算、坐标量级放大后的误差传递。

对应数据不要只给"普通随机点/随机线段"：额外准备极小夹角、接近平行、接近共线、相切、坐标接近上界、答案量级被放大的构造，并确认它们分别卡掉不同 `eps` 或不同比较写法的错解。题面范围、Checker 误差规则与数据设计必须一起收口（见 `references/checker-interactor.md` 工艺守则）。

## 6. 交互题错法轴

交互题的错法不只在"问了哪些数"，沿三条轴系统枚举，再挑出彼此独立、真像人会写出来的组合：

- **查询集合**：连续区间；特殊数集合（质数、幂次、小合数）；手工挑的"看起来覆盖很广"的集合。
- **查询顺序**：从小到大；从大到小；遇到第一个"看似安全"的结果就停；固定问满再答。
- **收尾策略**：输出第一个命中的对象；输出最后一次查询的对象；固定 fallback；把"没问过但看起来安全"的对象直接当答案。

想到某个"正向扫描"错法时，默认检查它的反向版本是否也是独立错法。对自适应交互题，若某个错解在当前 Interactor 下看起来等价正确，优先怀疑 Interactor 太弱，而不是认定错解不可卡（见 `references/checker-interactor.md`）。

## 7. 数据设计方法：每类错法一个"死亡模式"

对每一类保留的错法，至少找到一个明确、可复述的死亡模式，并固化为对应 `data.groups` 组：

- 错误贪心 → 局部最优害死全局的极端构造；
- 错误二分 → 非单调或恰好卡在转折点的构造;
- 错误 DP → 必须依赖被漏掉状态信息的构造；
- 复杂度错误 → 近上界、卡常数、卡重复预处理的构造；
- 实现错误 → 最小/最大规模、全相等、严格递增/递减、溢出临界、极值权重；
- 图算法错误 → 触发重复松弛、错误弹堆、错误 `INF` 的构造；
- 数学错误 → `n >= mod`、模数不互素、答案为 0、边界取整、精度敏感构造。

找不到稳定死亡模式时，用 `probhub stress` 对拍搜索反例，找到后固化进 secret 数据并登记数据组；不要保留"理论上会错但没有数据证明"的错解。

## 8. 数据强度纪律

### 8.1 数量下限

- 一个测试文件只含一组测试用例：至少 **30** 个测试文件；
- 一个测试文件含多组测试用例：至少 **20** 个测试文件；
- 题目规模太小、无法自然堆出这么多明显不同的数据时，在交付说明中写明原因，并用结构不同的极端构造尽量补足。

### 8.2 分布配比

重点不是凑够数量，而是让文件之间承担不同的卡错职责：

- 样例与教学型小数据：少量；
- 边界/极端结构：一批；
- 定向 hack（对应第 7 节死亡模式，登记 `data.groups` + `targets`）：一批；
- 接近时限的大数据（专门压常数、卡近 TL 解法）：一批；
- 纯随机：最后才补，只能作为补充。

### 8.3 数据预算主动打满

- 小随机组：把测试组数 `T` 打到题面允许的最大值；
- 中档随机组：把 `sum n`、`n * T` 或总输入长度打到最大值；
- 大数据组：把单组 `n` 打到最大值，再用多个不同 seed、不同结构的大数据覆盖；
- 大量随机数据优先用 testlib 随机数生成器批量生成；手写构造只承载你已明确知道的 hack 点。

### 8.4 与 ProbHub 机制的对应

- 每个定向组：`data.groups` 声明 `name`/`role: wrong-solution-killer`/`patterns`/`targets`；对应错解 `expected` 写明 `status` 与 `groups`，并 `forbid: [FAIL]`。
- 近上界大数据组：作为 `brute-killer`，brute 在其上 `expected: {status: TLE}`；brute 在其余数据上不得 WA。
- stress 找到的反例：固化为 secret 数据并归入相应组；复现方式见 `references/stress.md`。
